# CarConnect 0.1.10 OEM · SPP 重试保护测试

针对 BC03 1.7.9 实车“C1 → C2 → C4 → 超时 → 再次清理”的反馈，停止清理失败后的反复断开。固定基线为 OEM 0.1.9；不是 BC03 1.7.2 或 SD8227 启动兼容包。

## 安装后怎么用

1. 覆盖安装 `CarConnect-0.1.10-beta-OEM-SPP-guard-test-Android4.2-4.4.apk`，保留应用数据，不卸载。code52，同包名、同证书、纯 V1；已选 iPhone、热点、音量和自动连接偏好保留。
2. **先关闭自动连接**。在没有通话时，从原车蓝牙界面关闭再开启蓝牙，然后连接已配对 iPhone。这一步用于排除旧状态，会中断原车通话/蓝牙音乐；不删除配对、不重新选择 iPhone。不能保证原车一定清除缓存。
3. “允许底层 SPP 恢复（实验，默认关闭）”先保持关闭。原有清理开关单独保留，不会因为旧开关已开启而自动发送 VH。
4. 关闭再开启“自动连接”，观察一轮结果。通道空闲稳定 300ms 后继续原来的连接；此路径不发送 Binder 断开或 VH。

## 失败时的新行为

原服务清理最多请求一次，未确认释放则暂停本轮自动重试，显示 **P1 / SPP 状态未释放，本轮自动连接已暂停**。清理前同步写入未完成标记；标记跨进程和正常重启保存，不会因为冷却结束或重开应用而反复清理。确认空闲后自动清除标记，仍会在发送 VF 前核对原车手机及通道。

暂停的是当前服务的重试循环，保存的自动连接偏好没有被关闭。恢复原车蓝牙状态后，关闭再开启自动连接即可；正常重启后如果通道已空闲，也可按原偏好连接。这个保护不自动重启蓝牙，不修改 BC03 缓存、不伪造广播、不复用未知的占用通道。

若确需再次清理，等待任务退出，在设置里点击“允许再次清理一次”，再关闭/开启自动连接。按钮仅解除本应用的未完成标记，不发命令、不直接启动会话；当前连接任务或本应用数据通道仍在使用时拒绝操作。进程内原 45 秒清理冷却仍保留。

只有明确开启新增底层恢复选项时，原接口未释放才允许一次已核对 VH。VH 会断开该模块管理的 SPP 投屏连接；仍未收到释放状态就暂停，不循环重发。点击解除暂停后也不绕过占用校验。

**本版修复的是反复清理造成的干扰，不证明已经修复原车服务持续占用/缓存残留。** 若仍停在蓝牙连接，请复制 P1 前后的“原车通道诊断”和“诊断信息”完整文本，私下反馈。不要继续反复点击重试或开启底层恢复碰运气。

OEM 0.1.9 的手机保存与首帧恢复、iAP2、视频、音频、触摸、有线 USB 保持原逻辑。首帧恢复只在无线控制启动后生效，不能解决 VF 前清理失败。BC03 1.7.9 和 1.3.6 的精确指纹门禁、gocsdk 门禁保留；本包没有适配新的蓝牙服务版本。
