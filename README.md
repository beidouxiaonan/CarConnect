# CarConnect 0.1.6 beta · BC03 1.7.2 SPP 接入测试

分支：`codex/bc03-172-k2001n`。基于已发布的 `v0.1.5-beta-bc03-172-test` APK 增量修改，不使用 SD8227 分支。

显示版本：`Carplay-connect-0.1.6-beta-BC03-172-SPP-test`，versionCode 45。沿用包名和测试签名，可以覆盖安装保留已选择的 iPhone、热点和音量设置。最低 API17，纯 V1 签名，ARMv7；图片中的设备实际报告 API25，本次没有 Android4.4 或该机型的现场测试。

## 按图片调整了什么

- 旧版发送 VF 后，必须等 BC03 的 `isSppConnect()` 为真才向 `goc_spp` 登记手机地址，状态一直不更新就无法进入 iAP2 验证。
- 新版保留 15 秒等待。只有已核对指纹、版本为 1.7.2、手机没有变化时，状态缺失才允许一次数据接入测试；8 秒内收不到数据，关闭本应用客户端。仍由原有 iAP2 握手检查协议，不把缺失状态或收到字节当作 CarPlay 成功。
- 失败请求从 VF 写入开始至少间隔 45 秒，减少重复自动尝试给原车留下未完成请求。已有数据的会话关闭后可以正常重连。
- 连接诊断增加 S1～S6，明确区分 VF 的 51 字节、地址登记的 12 字节与真正协议数据的收发计数。

尚不能据图片确认原车是否已接受 VF、手机是否开放该 iAP2 服务。这个包用于验证和改善接入逻辑，不承诺已修复无线连接。

## 操作

1. 覆盖安装本次 **BC03 1.7.2 SPP-test** APK，打开原车蓝牙页面，确认 iPhone 通话蓝牙已连接，并开启车机热点。
2. 回到 CarConnect，取消“使用 USB 有线连接”，保留“自动连接”和“使用原车蓝牙连接 iPhone”。已有保存的手机不用重选。
3. 等待一次完整尝试。若显示冷却，等待提示倒计时结束。失败后打开“连接诊断”，记录 S1～S6 和收到/发送字节数，再复制“诊断信息”。

首次没有保存手机时，点“选择/更换 iPhone”并记住一次。记录仅保存选择，仍需要原车模块先连接这台手机。

这台 K2001N 曾在点击有线连接后整机重启，本次无线修改没有修复有线问题；测试时保持无线模式。

## 怎样看结果

| 最后信息 | 含义 |
|---|---|
| S1 | 本地 socket 可打开；尚不能证明原车 SPP 已连接 |
| S2 | VF 写入完成；不能证明原车接受或连接完成 |
| S3：已上报 SPP | 服务状态为真，开始登记数据客户端 |
| S3：未上报 SPP | 仅 1.7.2 在 15 秒后进行一次数据验证 |
| S4 / S5 | 已登记客户端并交给原有 iAP2；还不是 CarPlay 成功 |
| S6：8 秒无数据 | 状态缺失时接入仍无回包；需要原车建链/模块层进一步证据 |
| S6：收到首批数据 | 继续看原有 iAP2 握手结果；若失败，不能报连接成功 |
| iAP2 成功、进入 CarPlay | 才是端到端通过 |

没有新增系统权限、不替换 BC03/Bluetooth/gocsdk、不读取原车 UART 响应、不使用标准栈 `t3` 地址代替外接模块，不调用全局蓝牙断开。保留 0.1.5 音频/全屏优化与手机记忆。
