# CarConnect 0.1.7 beta · OEM SPP 自动清理测试

本版以 **CarConnect 0.1.4 beta OEM test Android4.2** 的已发布 APK 为基线，显示版本 `Carplay-connect-0.1.7-beta-OEM-SPP-cleanup-test`，versionCode46。不是 BC03 1.7.2 SPP 探测版，也没有混入 0.1.5 AV 分支。

## 操作

1. 覆盖安装测试 APK，原有手机、热点、音量和帧率记录保留。
2. 打开设置中的“无线连接、画面与音量设置”。保持“使用原车蓝牙连接 iPhone”开启，再勾选 **启动及连接前自动清理原车 SPP**。该开关默认关闭，设置会保存，关闭后不发送清理命令。
3. 原车蓝牙先连接已配对 iPhone，保持车机热点与手机 Wi-Fi 开启。以后启动 CarConnect 时在后台检查，并在原车无线连接前再次检查。
4. 连接失败时打开“连接诊断”，选择“复制原车通道诊断”，查看 C1、C2、C3 和最终错误。

首次启用会立即安排一次后台检查。正在建立连接时由连接前检查处理；CarConnect 自己的通道正在使用时跳过清理。应用页面重建不会再次清理当前会话。重启进程后会重新检查。

## 具体行为

- 没有 SPP 占用：不发送断开请求，正常连接。
- 有占用、开关关闭：保留占用报错，不抢占。
- 有占用、开关开启：调用已核对 BC03 服务的 `SppDisConnect()`，最多等待 5 秒，并要求未连接状态稳定 300ms。
- 请求返回不代表成功：只有 C3 表示状态已释放；不释放、接口异常、取消或手机变化均停止本次连接，不发送 VF。
- 清理请求至少间隔 45 秒，避免服务未响应时自动重试反复断开。已空闲通道无需等待冷却。

| 诊断 | 含义 |
| --- | --- |
| C1 未发现占用 | 不发送断开请求 |
| C1 检测到占用 | 已启用开关，准备请求原车断开 |
| C2 请求返回 | 服务接受了调用；不等于通道已释放 |
| C3 稳定 300ms | 已观察到稳定的未连接状态，可以继续原有连接流程 |
| 清理超时 | 服务仍占用或状态没有稳定，本轮停止，不发送 VF |
| 清理冷却 | 上次请求不足 45 秒，不重复发送 |
| 自己的通道正在使用 | 不清理 CarConnect 当前会话 |

## 范围和限制

仅适用于 0.1.4 已核对的 **BC03 1.7.9 / 1.3.6 与指定 gocsdk 指纹**。开启会中断原车当前管理的 SPP 投屏/数据连接。原车服务只暴露一个 SPP 状态和断开入口，普通 APK 无法列举或强杀系统中所有 SPP 连接、其他进程或蓝牙模块。

本版不请求关闭整个蓝牙、不删除配对、不请求断开 HFP/A2DP、不读抢原车 UART。原厂实现或联动仍可能影响连接，需实车验证。如果原服务的断开实现为空或状态不更新，会明确超时，不改写状态强行连接。

最低 API17，兼容 Android4.2 / 4.4 的安装要求，ARMv7、纯 V1 签名；沿用原测试签名和包名可覆盖安装。27 项本地测试与 APK 静态检查通过，**尚未实车验证，不能承诺已解决所有占用或连接失败**。既有有线重启问题与 VF 后无 SPP 状态问题不在本次修复范围。
