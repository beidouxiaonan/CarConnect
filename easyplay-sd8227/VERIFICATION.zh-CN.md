# 0.1.7 MultiDex 兼容测试验证（2026-10-08）

## 故障证据与边界

用户提供完整 0.1.6 启动记录，实际 SDK=17，显示 Android=4.4.2；设备标识 AC822X / ac8317 / autochipsac83xx。失败点为 MultiDex 寻找三参数 `DexPathList.makeDexElements`。本地主 DEX 反汇编确认只保留固定 V19 调用，旧路径不存在。尚未取得设备的方法清单，所以两参数工厂存在与否由新包探测确认。本次不发布用户完整日志。

## 已验证

- 16 项 JVM 测试：14 项工厂签名分派与原类路径保护，覆盖私有继承字段、两/三/四参数、List 与 ArrayList、静态与实例方法、选择优先级、显式与隐藏 I/O 失败、空/缺失/类型异常返回、未知签名拒绝、原类路径顺序及失败后重试；另 2 项恢复决策测试。
- 3 项 Manifest 语义回归：唯一 Launcher、原 Activity 保留、仅检查入口关闭硬件加速、既有服务/广播/权限/SDK 不变。共 **19 项回归测试通过**。
- 主 DEX：原 219 个类中 218 个完全不变；MultiDex 只替换一个 installer 调用，方法其余内容、解压与重试逻辑不变；新增 12 个主 DEX 辅助类（含内部类）。
- classes3.dex：原 8192 个类中 8191 个完全不变；原 Activity 全部业务方法原样保留，仅原有启动恢复包装。classes2.dex 与 classes4.dex 逐字节不变。
- 所有新增 Java 代码只使用 API17 编译依赖，DEX 035。API17/19/24 签名验证及 zipalign 通过，原证书一致，仅 V1，无 V2/V3/V4 签名块；ZIP CRC 和载荷校验通过。
- APK versionCode 48，minSdk 17；包名与存储键不变。原 resources、assets 与三个 armeabi-v7a 库逐字节一致。原签名元数据的四项 V1 警告仍为基础包继承内容。

## 尚未验证

没有该车机在本次新包上的实测结果。JVM 测试验证反射分派与类路径追加，不运行 Dalvik dexopt；签名与结构验证不证明设备能启动、无线/有线连接成功或长期稳定。需要覆盖安装后确认 `MULTIDEX_OK` 与 `MAIN_RESUMED`，若仍失败继续查看新堆栈。
